Build a website that feels deliberately art-directed and makes the next customer action obvious.

## Workflow
1. Read the business brief: service, audience, location, offer, approved claims, assets, and desired enquiry channel. For a demo, choose fictional content and label it. For a real business, do not invent reviews or results.
2. Load `frontend-design` if available; otherwise read `references/design.md`.
3. Open https://saaspo.com/ in an available browser. Use Pages or Sections and the Style / Industry filters to find a suitable reference. Prefer the user's chosen reference. Inspect the actual screenshot or rendered site, not just its metadata. If browsing is unavailable, ask for a screenshot or proceed with an explicitly original direction; never claim to have inspected it.
4. Write a short `DESIGN.md`: exact reference URL, observed grid and section order, type scale, spacing, image treatment, CTA placement, and how each will change for this business. Borrow design principles, not logos, copy, claims, or proprietary assets. A SaaS pricing page may inspire service packages, but don't add SaaS features to a salon.
5. Copy the `assets/` starter into the user's destination, without overwriting unrelated files. Adapt every section and the visual direction. This starter is an example, not a mandatory aesthetic.
6. Make the primary CTA real. The demo prepares an enquiry locally; configure a client-approved email/WhatsApp address before release. Avoid fake booking confirmations.
7. Check at 390px and desktop widths: no overflow, legible contrast, usable navigation, labelled fields, keyboard focus, working enquiry and image fallback. Report what you actually verified.

## Handoff
Return preview/run instructions, customized source, DESIGN.md and a short list of remaining client content. Publishing requires the user's requested destination. Read `references/video.md` when preparing a tutorial.
